# Track Spectrogram Timeline Mode

## Context

Add a per-track timeline display mode that switches between the existing waveform and a standard spectrogram without changing selection, clip editing, scrolling, zooming, playback-follow, or track resizing. Spectrogram mode exposes session-only Viridis, Inferno, and Grayscale palettes plus 512, 1024, 2048, and 4096-sample FFT windows (2048 default). Analysis uses the installed `@descript/web-audio-js` `RawDataAudioContext`/`AnalyserNode`, including its fixed Blackman window; a bounded cache exists only while that track remains in spectrogram mode.

## Approach

1. **Define the spectrogram analysis contract and deterministic palette mapping.**
   - Add `src/ui/timeline/SpectrogramAnalysis.ts`; no equivalent exists because `SummaryGenerator` emits waveform extrema, not frequency bins.
   - Export `SpectrogramPalette = 'viridis' | 'inferno' | 'grayscale'`, `SpectrogramWindowSize = 512 | 1024 | 2048 | 4096`, `TrackDisplayMode = 'waveform' | 'spectrogram'`, and `TrackDisplaySettings { mode, palette, windowSize }`. Export `DEFAULT_TRACK_DISPLAY_SETTINGS` as `{ mode: 'waveform', palette: 'viridis', windowSize: 2048 }` and the ordered window-size/palette options for the UI.
   - Export `SpectrogramAnalyzer`, constructed with `(sampleRate: number, windowSize: SpectrogramWindowSize)`, with `analyzeWindow(samples: Float32Array, output: Uint8Array): void` and `dispose(): void`. Internally create one mono `RawDataAudioContext` with block size `Math.min(1024, windowSize)` and a mutable looping source through the existing `createRenderingAudioSource` helper. Connect `source.node → analyser → audioContext.destination`, call `audioContext.resume()`, set `analyser.fftSize = windowSize` and `smoothingTimeConstant = 0`, and allocate one block-sized output scratch buffer.
   - `analyzeWindow` requires exactly `windowSize` centered samples. For each successive `blockSize` chunk, copy it into `source.channelData[0]` and call `audioContext.process([outputScratch])`; after exactly `windowSize / blockSize` process calls, query `getFloatFrequencyData`. This explicit pull loop is required for `RawDataAudioContext` and makes each column independent of earlier columns because the analyser’s complete rolling window has been replaced.
   - Treat non-finite values and the patched package’s exact `0` silence sentinel as the floor, clamp the fixed display range `[-100, 0]` dB, and pack each bin into `0..255`. Do not implement another FFT, window function, smoothing, gain correction, or zero-padding factor. `dispose()` disconnects both graph edges and suspends/releases the raw context.
   - Map packed intensity to RGBA at paint time, not analysis time, by linear interpolation between evenly spaced stops: Viridis `#440154/#3b528b/#21918c/#5ec962/#fde725`, Inferno `#000004/#420a68/#932667/#dd513a/#fca50a/#fcffa4`, and Grayscale `#000000/#ffffff`. Palette changes therefore reuse cached magnitudes.

2. **Build a mode-scoped, worker-backed tile cache over raw clip PCM.**
   - Add `src/ui/timeline/SpectrogramWorker.ts` and `src/ui/timeline/SpectrogramCache.ts`; keep this separate from process-global `SummaryGenerator` and playback `AudioFileCache` because their lifetimes and data shapes do not match the requested mode lifetime.
   - `SpectrogramCache` owns exactly one module worker created with `new Worker(new URL('./SpectrogramWorker.ts', import.meta.url), { type: 'module' })`, a bounded request queue, pending request promises/consumers, one current source registration per clip, resolved tiles, a monotonic generation, and `dispose()`. Its constructor is `(projectDirectory: string, sampleRate: number, windowSize: SpectrogramWindowSize)`; its request API is `getTile(clip: Clip, channel: number, hopSize: number, tileIndex: number, signal: AbortSignal): Promise<SpectrogramTile>`, where `SpectrogramTile` exposes `firstColumn`, `columnCount`, `frequencyBinCount`, and column-major `Uint8Array data`.
   - Register source files by clip id, not by retaining every observed clip length. On the first request, obtain the current immutable `File` through `FileSystemUtils.getFileHandle(projectDirectory, clip.filename).getFile()`, derive available frames from `file.size / (Float32Array.BYTES_PER_ELEMENT * channelCount)`, and post `replace-source { clipId, file, availableFrames, sourceRevision }`. If a requested centered window extends beyond the registered frames while `clip.length` has grown, deduplicate one refresh and retry at most once per 500 ms for that clip. When `file.size` grows, replace the worker’s prior `File`, increment `sourceRevision`, and discard that clip’s pending/resolved tiles before serving new work; if it has not grown, zero-pad the missing tail until the next bounded refresh. This leaves at most one `File` snapshot per clip in the mode-scoped cache, including MemoryBackedFileSystem where `getFile()` copies the file.
   - Define one analysis tile as 128 columns for one source clip/channel. For current timeline scale use `hopSize = Math.max(8, Math.round(samplesPerUnit))`; absolute source column `k` is centered at clip sample `k * hopSize`, and tile `t` contains global columns `t * 128 .. t * 128 + 127`. Key pending/resolved entries by clip id, source revision, channel, sample rate, window size, hop size, and tile index. Translation is deliberately absent, so horizontal scrolling reuses exact tiles; a zoom produces a different hop key without stretching old data; clip-view movement/trim remaps the same source tiles.
   - In the worker, read headerless interleaved Float32 PCM using the byte convention already used by `SummaryGenerator` and `AudioFileReader`. For each column, deinterleave only its requested channel into a centered `windowSize` frame, zero-fill before sample 0 and after the registered available frames, pass it to `SpectrogramAnalyzer`, and write column-major `Uint8Array` output of `128 * (windowSize / 2)` bins. Coalesce overlapping source reads when `hopSize <= windowSize`; otherwise load sparse windows in batches of at most 16 so a zoomed-out tile neither reads the skipped PCM nor creates an unbounded set of simultaneous `arrayBuffer()` calls. Transfer the packed result buffer back to the cache.
   - Limit the cache to two worker-posted requests (one running and at most one waiting); keep additional missing tiles in a cache-side FIFO. `Waveform` enqueues a viewport’s missing tile indices nearest its center first, so FIFO preserves visible priority without another API parameter. Each pending entry owns one underlying job promise plus a set of per-call consumer wrappers tied to their `AbortSignal`. Aborting one consumer rejects only its wrapper; when all consumers abort, remove an undispatched tile or send `cancel { requestId }`. The worker yields after every eight columns, observes cancellation between chunks, returns `cancelled`, and advances to the newest queued request. A completed tile may remain cached even if its viewport consumer subsequently aborts, but obsolete rapid zoom/scroll work must not delay the current viewport.
   - Deduplicate concurrent requests through that shared underlying job. On a live failure remove the pending entry so a later draw can retry; cancellation is silent. Retain resolved tiles in access-order LRU capped at 32 MiB per active track, evicting least-recently-used resolved tiles while excluding pending jobs and the value being returned. Color is never part of the key.
   - `dispose()` marks the generation dead, aborts queued/in-flight requests, terminates the worker, rejects/ignores pending work, drops current `File` registrations and typed arrays, and makes later requests fail immediately.

3. **Make `Waveform` switch renderers while preserving its SVG interaction contract.**
   - Extend `Waveform` in `src/ui/timeline/Waveform.ts` with session-local `TrackDisplaySettings`, nullable `SpectrogramCache`, a draw-generation counter and `AbortController`, a disposed flag, a one-error-per-cache guard, and a retained `ResizeObserver`. Extend its constructor with `projectDirectory: string` and `initialDisplaySettings: TrackDisplaySettings`; add `getDisplaySettings(): TrackDisplaySettings`, `setDisplaySettings(settings: TrackDisplaySettings): void`, `setIndex(index: number): void`, and `dispose(): void`.
   - `setDisplaySettings` creates the cache on waveform→spectrogram, disposes it on spectrogram→waveform, and disposes/recreates it when `windowSize` changes. A palette-only change retains the cache. Every change aborts the prior draw, clears the obsolete visual surface, and redraws this track. Settings remain ordinary controller state; do not add fields to `Track`, call `ProjectManager.saveTrack`, or change persistence/archive schemas.
   - `setIndex` updates the public row index, `var(--waveform-${index})` clip background color, and every existing `ClipViewController`’s rect fill. This lets `TrackListController` reuse the same Waveform/cache when track insertion/deletion changes row indices instead of ending a still-active mode through reconstruction.
   - Keep `topSvgElement`, `clipViewGroupElement`, clip body/header hit targets, `topGroupElement` selection overlays, channel separators, automation overlays, and trim handles in their existing order. In spectrogram mode hide/clear only the three waveform paths. Make `drawAxes()` omit waveform center lines while retaining the left boundary and channel separators.
   - Give each visible `ClipViewController` one pointer-events-none SVG `foreignObject` containing a canvas, inserted above the clip background and below headers/selections/handles. Size the backing canvas by `devicePixelRatio`; paint one vertical lane per source channel, linear frequency from 0 Hz at the lane bottom to Nyquist at the top, and map bytes through the selected palette. Paint the full clip-view interval, including overlap regions; multiply alpha by the same equal-power fade-in/fade-out implied by `startCrossFadeDuration`/`endCrossFadeDuration` so overlapping clip views remain legible and consistent with playback.
   - Reuse the exact visible track→clip conversion already in `ClipViewController.drawWaveform`: `realStart = max(0, visibleStart - clipView.startPosition) + clipView.offset` and `realEnd = min(visibleEnd - clipView.startPosition, clipView.length) + clipView.offset`. Request only tile indices intersecting that source range, and place each source column at track sample `clipView.startPosition + (columnCenter - clipView.offset)` through `getXValueForSample`; clip paint to the clip view and viewport. Aggregate multiple columns landing in one canvas pixel with per-bin maximum intensity; stretch a lone column to the midpoint boundaries between adjacent centers when zoomed in.
   - Mirror the existing waveform node lifecycle: include the spectrogram surface in `drawClipViewOver`, `drawMoveInProgressClipView`, trim-preview bounds, `reset`, resize, and `remove`. At move/trim start, render the same extended visible range the waveform path currently requests so translated or newly exposed portions appear during the gesture without analyzing a whole offscreen clip.
   - Compute a stable render-state key before each `drawAudioData` from cache identity, mode/palette/window, width/height/device pixel ratio, translation, `samplesPerUnit`, and the ordered visible clip-view identity/start/offset/length plus each source clip length. If it equals the current key, keep the existing `AbortController` and in-flight/completed canvas work and return without resubmitting tiles; this is required because playback-follow calls `drawAudioData()` every animation frame even when the viewport is stationary. When the key changes—or on explicit mode, palette, window, move/trim-preview, or teardown changes—abort the prior controller, create a new one, increment the draw generation, and enqueue tiles nearest the viewport center first. Capture the key, generation, cache identity, settings, and viewport bounds for every async draw; paint only if its signal is live and all captured state still matches. A completed tile may remain in the still-live cache after its consumer becomes stale. On a live worker/read failure, clear the current render-state key so a later redraw retries, leave the affected area blank, and report `Could not render spectrogram` through `NotificationsController` once for that cache instance; cancellation is silent, and recreating the cache permits one new report.
   - Add `PointerStateManager.removeWaveform(waveform: Waveform): void`. If the waveform is the active hover target, owns `activeClipViewController`, or owns `clipViewMoveInfo.clipViewController`, call `reset()` before any associated controller is removed; otherwise leave another track’s active gesture untouched. `dispose()` first invokes this method, then marks itself disposed, aborts the draw, increments the generation, disposes the cache, disconnects the `ResizeObserver`, and removes all clip controllers/context menus and canvases.

4. **Add compact per-track View controls without persisting them.**
   - Change `TrackListTrack`’s constructor to accept initial `TrackDisplaySettings` and `(settings: TrackDisplaySettings) => void`. Replace the Effects-only grid cell with `.track-action-controls`, retaining the existing Effects button and adding a `View` button.
   - The View button opens a body-level native `popover="auto"` (the established `#menu-dropdown` pattern avoids `.track-info { overflow: hidden }`). Use ids `track-display-button-${track.id}`, `track-display-settings-${track.id}`, `track-display-mode-${track.id}`, `track-spectrogram-palette-${track.id}`, and `track-spectrogram-window-${track.id}`; give the trigger `aria-haspopup`, `aria-controls`, and synchronized `aria-expanded`.
   - Populate labelled native selects with Waveform/Spectrogram, Viridis/Inferno/Grayscale, and `512/1024/2048/4096 samples`. Disable palette/window selects in waveform mode but retain their values. Each change constructs the complete settings object and invokes the callback immediately; no save or undo entry is created because these are session-only view choices.
   - Extend `TrackListTrack.remove()` to remove its body-level popover. Add focused styles in `index.css` for `.track-action-controls`, `.track-display-button`, `.track-display-settings`, and `.track-display-setting`, reusing current-color borders, `var(--bg-color)`, `var(--menu-bg)`, and inherited font instead of adding a second visual system.

5. **Wire settings and exact teardown through `TrackListController`.**
   - In the sole track-row construction path in `src/ui/timeline/TrackListController.ts`, create `new Waveform(this, project.directoryName, track, waveformDiv, index, DEFAULT_TRACK_DISPLAY_SETTINGS)` before `TrackListTrack`, and pass a direct callback from the View controls to `waveform.setDisplaySettings`.
   - Reconcile existing pairs by track id regardless of prior row index: call `existing.controller.setIndex(i)`, reuse its info/waveform DOM and controllers, and retain its session settings and live spectrogram cache. On active project-id change, dispose every old pair before clearing the maps; newly constructed tracks start at defaults, so switching projects or reloading resets modes and choices as requested. Deleted tracks dispose and drop their pair.
   - Before every actual pair-removal path—project-id reset and missing/deleted track—call both `pair.controller.dispose()` and `pair.infoController.remove()`. Keep the existing `zoom`, `translate`, `draw`, resize, history, project-listener, and playback-follow routes unchanged; they remain the only scale/origin drivers and now dispatch to the active renderer through `Waveform.draw()`/`drawAudioData()`.

6. **Protect the uncertain analyser behavior with focused tests.**
   - Add `src/ui/timeline/SpectrogramAnalysis.test.ts` using the project’s existing `RawDataAudioContext` test style. Verify an all-zero 2048-sample frame packs to all-zero intensity; this specifically guards the installed analyser implementation’s observed `0 dB` sentinel for non-finite silence. Verify a 1 kHz sine at 48 kHz places the packed spectrum’s strongest region at the expected `round(1000 * 2048 / 48000)` bin (allow the adjacent Blackman-window bins) and leaves distant bins lower. These tests defend visible frequency placement and silence handling, not internal graph wiring.

## Critical files & anchors

- `src/ui/timeline/Waveform.ts` — `Waveform.draw/drawAudioData/resize`, `drawAudioDataForCanvasXRange`, and `ClipViewController.drawWaveform` are the renderer, viewport mapping, and interaction-layer anchors.
- `src/ui/timeline/TrackListController.ts` — project-listener reconciliation around `infoWaveformPairs` is the sole constructor and all teardown/reorder paths; `zoom`, `translate`, and `draw` are the viewport drivers.
- `src/ui/timeline/TrackListTrack.ts` — constructor-built title/effects/mix/gain/pan controls and `remove()` are the View popover integration and cleanup points.
- `src/ui/PointerStateManager.ts` — active waveform/clip/gesture fields and `reset()` require the dedicated safe teardown path before a spectrogram track is removed.
- `src/rendering/RenderingAudioSource.ts` — `createRenderingAudioSource` is the established mutable-block source for driving `RawDataAudioContext` synchronously; pair it with the explicit `process()` loop used by `RenderingJob`.

## Assumptions & contingencies

- Spectrogram settings are deliberately session-only: active-project changes and reloads reset to Waveform/Viridis/2048. Reindexing a track within the active project reuses its controller, so its mode, settings, and cache remain alive.
- Spectra represent each source clip/channel before track gain, pan, effects, or crossfade summation, matching the existing waveform renderer’s source-oriented semantics. Crossfade regions communicate fades through display alpha rather than recomputing the mixed playback signal.
- The target browser supports the native Popover API and structured cloning of `File`, both already assumed by the application’s Chromium-oriented UI/worker stack. If the latest `File` is shorter than `clip.length * channelCount * 4` during an in-progress recording, treat missing tail frames as zero and retry the deduplicated source refresh no more often than every 500 ms; do not block timeline rendering.
